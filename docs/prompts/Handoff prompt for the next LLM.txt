## 1. Project overview

Propora is designed for real-estate agencies and property managers. It includes:

* A public property discovery website.
* Property listing and management.
* Agent management.
* Customer and lead management.
* Viewing requests and scheduling.
* An administrative dashboard.
* Basic analytics and notifications.

## 2. Technology stack

* Next.js 16 with App Router
* React and TypeScript
* Tailwind CSS
* shadcn/ui
* pnpm
* MongoDB and Mongoose
* Zod

Use Server Components by default. Use Client Components only when interactivity requires them.

The architecture is a **modular monolith** with feature-based organization. Avoid introducing unnecessary services, libraries, or abstractions.

## 7. Design and code standards

I want Propora to look like a polished, modern, professionally engineered product—not a generic AI-generated dashboard.

Maintain consistent:

* Page gutters and component padding.
* Spacing and typography scales.
* Border radii, borders, and shadows.
* Button, input, card, badge, and table styles.
* Responsive layouts and interaction states.

Prefer semantic classes such as:

```tsx
bg-background
text-foreground
bg-card
text-muted-foreground
border-border
bg-primary
text-primary-foreground
```

Avoid scattering hardcoded hex values throughout components.

Use restrained styling, clear hierarchy, realistic fictional content, and purposeful whitespace. Avoid excessive gradients, unnecessary animations, repetitive cards, and decorative elements that do not improve usability.

For code:

* Use strict, meaningful TypeScript types.
* Avoid `any` and unnecessary type assertions.
* Keep components focused and reusable where appropriate.
* Keep business logic out of UI components.
* Follow existing naming conventions.
* Handle loading, empty, error, and success states.
* Never claim code has passed tests unless it has actually been verified.
